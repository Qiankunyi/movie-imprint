# 电影印记：MVP 字段与标签冻结 v1

- 状态：产品字段基线
- 日期：2026-08-01
- 依据：3 个完整手工案例＋12 条代表性感想验证集
- 目的：供移动端低保真原型、AI 输出协议和开发交接共同使用
- 冻结含义：除非真实原型测试证明无法完成记录，否则不再增加核心模块、态度选项或顶层实体

---

## 1. 冻结结论

MVP 固定为六个层次：

1. 作品 Work；
2. 观影／放映场次 Viewing Event；
3. 感想记录 Imprint Record；
4. 原始层 Raw Layer；
5. 印记层：态度、情绪、记忆卡片；
6. 行动层：后续关系与推荐判断。

用户日常不会依次填写六层。标准流程仍是：

> 输入作品名与原始感想 → 可选导入票务 → AI 生成草稿 → 用户快速确认 → 保存

底层结构完整，界面逐步显露。

---

## 2. MVP 产品范围冻结

## 2.1 默认支持

- 动画电影；
- 真人电影。

## 2.2 影院特别放映有限例外

允许记录：

- TV 动画先行上映；
- 若干集连续影院放映；
- 影院特别篇／特别放映；
- 带舞台挨拶、映前谈、映后谈的同类线下活动。

限制条件：

- 必须发生在线下影院或明确的线下放映活动；
- 必须记录放映的作品名，并用集数范围或自由说明标明放映内容；
- 使用电影版相同的票务、场次、态度、情绪和记忆卡片流程；
- 不支持普通在家观看；
- 不支持季度追番、进度管理和逐集日记；
- 不因此扩展到电视剧、游戏、漫画或小说。

产品界面默认仍显示“记录一部电影”。“影院特别放映”是次级入口，不与电影入口并列争夺注意力。

## 3. 顶层实体冻结

## 3.1 作品 Work

| 字段 | 必填 | 说明 |
|---|---:|---|
| `work_id` | 是 | 稳定内部 ID |
| `title` | 是 | 用户当前使用的作品名 |
| `original_title` | 否 | 原文片名 |
| `work_type` | 否 | 动画电影、真人电影、影院特别放映；默认未指定 |
| `aliases` | 否 | 其他译名和常用名 |
| `release_year` | 否 | 只用于消歧 |
| `external_refs` | 否 | Bangumi、豆瓣等外部 ID／URL |
| `identity_status` | 是 | 已匹配、本地条目、待检查 |

`work_type` 固定值：

- `animation_movie`；
- `live_action_movie`；
- `tv_animation_special_screening`；
- `unspecified`。

不增加“纪录片”“实验电影”等更多顶层枚举；这些仍属于真人电影或动画电影，可通过自定义标签表达。

## 3.2 观影／放映场次 Viewing Event

| 字段 | 必填 | 说明 |
|---|---:|---|
| `viewing_id` | 是 | 稳定场次 ID |
| `work_id` | 是 | 关联一个作品 |
| `viewed_on` | 否 | 实际观看日期 |
| `screening_at` | 否 | 放映开始时间，带时区 |
| `screening_ends_at` | 否 | 放映结束时间，带时区 |
| `viewing_relation` | 否 | 初看、重看、未指定 |
| `watch_index` | 否 | 第几次观看 |
| `location_type` | 否 | 电影院、家中、其他、未指定 |
| `screened_content` | 条件必填 | 电影可省略；特别放映必须填写集数范围或自由说明 |
| `viewing_context` | 否 | 影院／家中详细字段 |

`screened_content`：

```text
kind: full_movie | episodes
episode_start: 可空
episode_end: 可空
display_label: 例如“前三话”
```

特别放映使用 `episodes`；电影默认 `full_movie`。

## 3.3 感想记录 Imprint Record

| 字段 | 必填 | 说明 |
|---|---:|---|
| `record_id` | 是 | 稳定记录 ID |
| `work_id` | 是 | 关联一个作品 |
| `record_kind` | 是 | 观影感想或后续补充 |
| `linked_viewing_ids` | 是 | 可关联零个、一个或多个场次 |
| `related_record_ids` | 否 | 关联以前的感想或补充 |
| `recorded_at` | 是 | 实际记录时间 |
| `impression_source_*` | 否 | 现场、Bangumi、豆瓣、微博等来源字段 |
| `source_attitude_raw` | 否 | 来源平台原始星级／分数／文字态度 |
| `status` | 是 | 草稿、AI 草稿、仅原文正式记录、完整正式记录 |

一条感想在 MVP 中只属于一个作品。跨作品比较通过记忆卡片的“其他作品联想”表达，不建立一条感想同时属于多部作品的关系。

## 3.4 原始层 Raw Layer

固定字段：

- `raw_text`；
- `raw_text_format`；
- `raw_text_hash`；
- `raw_saved_at`；
- `raw_revisions`。

原文由用户主动修改，AI 永远不能回写覆盖。

## 4. 个人态度冻结

个人态度保持五项，不再增加：

| 值 | 界面文案 | 含义 |
|---|---|---|
| `love` | 超喜欢 | 强烈击中，对自己有明显意义 |
| `like` | 喜欢 | 存在足以认可这次体验的内容 |
| `neutral` | 无感 | 没有明显喜欢或排斥 |
| `dislike` | 不喜欢 | 不适合自己，或存在明显反感 |
| `mixed` | 不好说 | 喜恶与复杂感受无法被前四项概括 |

规则：

- “有喜欢的点”归入喜欢；
- “不适合我”和“反感”归入不喜欢，细节由情绪与卡片表达；
- 不增加“暂不判断”；
- AI 可以建议，用户确认前不成为正式态度；
- “仅保存原文”不强迫选择态度。

## 5. 情绪反应标签冻结

标签按组折叠。AI 通常只建议 3–7 个，用户不会在首屏看到完整列表。

- 开心

- 浪漫
- 温暖
- 心动
- 满足
- 爽快
- 治愈

## 5.2 强烈触动

- 感动
- 震撼
- 兴奋
- 热血
- 落泪
- 共鸣
- 敬佩

## 5.3 消极体验

- 悲伤
- 压抑
- 愤怒
- 恐惧
- 不适
- 恶心
- 失望
- 遗憾
- 无聊
- 反感

## 5.4 认知反应

- 意外
- 困惑
- 受到启发
- 开拓视野
- 想深入思考

## 5.5 持续感受

- 怀念
- 向往
- 意犹未尽
- 空虚
- 后劲很大
- 久久不能释怀

## 5.6 沉浸状态

- 紧张
- 代入
- 沉浸
- 着迷
- 忘记时间

## 5.7 交流冲动

- 想讨论
- 想推荐
- 想吐槽
- 想找同好

冻结规则：

- 预设标签共 46 个；完整但不平铺；
- 用户可以新增自定义标签；
- 自定义标签不自动成为全局预设；
- 近义口语优先映射，例如“难绷”可映射为有趣、尴尬或自定义，不能机械固定；
- 态度与情绪独立，“超喜欢＋遗憾”“不喜欢＋可爱”都合法。

## 7. 记忆卡片字段冻结

| 字段 | 必填 | 说明 |
|---|---:|---|
| `card_id` | 是 | 稳定 ID |
| `type` | 是 | 预设或自定义类型 |
| `title` | 否 | 浏览用短标题 |
| `content` | 是 | 记住了什么 |
| `why_it_matters` | 否 | 为什么记住或重要 |
| `related_emotions` | 否 | 关联情绪标签 |
| `linked_viewing_ids` | 否 | 关联特定场次或多场比较 |
| `evidence` | 否 | 原文依据 |
| `is_core` | 是 | 是否核心记忆 |
| `order` | 是 | 展示顺序 |
| `provenance` | 是 | AI 建议、用户接受／修改／新增 |
| `custom_fields` | 否 | 类型模板补充字段 |

证据字段固定包含：

- `excerpt`；
- `basis`：明示／推测；
- `voice`：用户／引用他人／来源元数据；
- `claim_mode`：直接感受／观察／解释／转述；
- `explanation`；
- `confidence`。

## 8. 观看场景字段冻结

## 8.1 所有场次共用

- 观看地点类型；
- 初看／重看；
- 第几次观看；
- 日期；
- 开始／结束时间；
- 独自／与他人／未记录；
- 连续看完／分段／未看完／未记录；

- 影院名称；

- 放映制式；
- 制式细节；
- 座位数组与座位数；

- 活动属性；
- 入场内容；

- IMAX；

场次属性首版：

- 首映；
- 先行上映；
- 重映；
- 应援上映；
- 午夜场；
- 多集连映；
- 特别放映；
- 其他。

活动属性首版：

- 声优舞台挨拶；

- 直播转播；
- 映前谈；
- 映后谈；

## 8.3 家中／个人设备

- 电视、电脑、平板、手机、投影、其他；

## 10. 推荐判断冻结

用户选择时只有：

- 会；
- 看对象；
- 不会。

可以留空，不增加“暂不判断”按钮。

条件字段：

- 推荐对象；
- 推荐理由；
- 注意事项；
- 不推荐原因；
- 作品问题／个人不适合；
- 仍值得肯定的部分。

推荐值只由用户主动选择。来源平台“力荐／推荐”等不能被 AI 转换为“会／看对象／不会”的建议值；用户选择后，原文中明确表达的理由才可用于协助填写条件字段。

## 11. 票务导入字段冻结

处理链：

> 本地拆分消息 → 本地去除敏感信息 → 模板提取 → 必要时 AI 补充 → 用户确认 → 建立场次

固定输出：

- 检测到的消息数；
- 一个或多个场次数组；
- 清洗后的电影／作品名；
- 起止时间；
- 城市、影院、影厅；
- 制式与制式细节；
- 座位数组和座位数；
- 票务提供商；
- 场次属性；
- 去除的敏感信息类型；
- 解析警告。

默认不保存：

- 姓名；
- 邮箱和手机号；
- 订单号；
- 取票码；
- QR 地址和令牌；
- 会员入口；
- 票价、票种和支付信息；
- 原始票务邮件。

## 12. 明确删除或不加入的字段

以下内容经过样本验证后仍不进入 MVP 核心字段：

- 数字评分；
- 客观完成度；
- 剧情、作画、音乐等维度分数；
- 强制剧情简介；
- 自动网络口碑；
- 文章字数类型：短评／长评；
- 强制唯一核心记忆；
- 强制推荐选择；
- 强制观看日期与地点；
- 同行者身份；
- 用户本人具体座位；
- 票价和购票订单；
- 每个角色、场景或配角的完整覆盖；
- 日常 TV 动画季度、进度与逐集字段。

---

## 13. 冻结后的变更规则

后续新想法按以下顺序处理：

1. 能否用现有字段表达；
2. 能否用自定义标签或自定义卡片表达；
3. 能否作为类型模板提示，而不是新字段；
4. 是否由至少两个真实案例证明是重复需求；
5. 是否会增加普通记录流程的思考负担。

只有同时证明“现有结构无法表达”和“重复出现”时，才允许修改冻结基线。

---

## 14. 原型阶段验收重点

移动端低保真原型必须证明：

- 首屏仍然只有作品名、原始感想和观看地点快捷选择；
- 特别放映入口不会干扰普通电影记录；
- 46 个情绪标签不会被一次平铺；
- 44 个记忆卡片类型通过分组、搜索和最近使用降低负担；
- 一条普通感想可在数分钟内确认完成；
- 多场次、票务导入和高级影院字段只在需要时展开；
- 用户可以仅保存原文；
- 用户可以看懂哪些是自己说的、哪些是 AI 推测、哪些是引用他人。
