## 1. 原型结论

MVP 使用一条主流程和两个按需分支：

```text
首页
  └─ 记录一部电影
       ├─ 普通输入 ───────────────┐
       ├─ 影院票务粘贴与确认 ────┤
       └─ AI 整理 → 确认工作台 → 预览与保存

首页次级入口
  └─ 记录影院特别放映
       └─ 作品名＋放映内容 → 同一条后续流程
```

设计约束：

1. 首页只有一个主按钮：“记录一部电影”。
2. “影院特别放映”是文字型次级入口，不与主按钮竞争。
3. 普通电影首屏只要求电影名和原始感想。
4. 观看地点是快捷选择，但普通电影可以先不填。
5. 票务导入只在选择电影院后出现。
6. AI 失败、离线或用户暂时不想整理时，都可以只保存原文。
7. 确认工作台默认只展开当前最需要确认的一组内容。
8. GitHub 同步永远发生在正式保存之后，并由用户单独触发。

## 2. 页面地图

| 页面 | 主要任务 | 是否进入普通主流程 |
|---|---|---:|
| 记录库／首页 | 开始记录、恢复草稿、查看最近记录 | 是 |
| 新建电影记录 | 输入片名、原始感想和观看地点 | 是 |
| 新建影院特别放映 | 输入作品名、放映内容和原始感想 | 次级入口 |
| 票务粘贴层 | 粘贴一封或多封预订邮件 | 条件进入 |
| 票务确认页 | 检查拆分后的场次与脱敏结果 | 条件进入 |
| AI 整理状态页 | 显示保存与整理状态 | 是 |
| 确认工作台 | 确认态度、情绪、卡片、场次和行动 | 是 |
| 卡片类型库 | 搜索、分组选择记忆卡片类型 | 条件进入 |
| 最终预览与保存 | 检查正式资产并保存 | 是 |
| 作品详情页 | 查看时间线、重看与后续补充 | 保存后进入 |
| 设置页 | AI、GitHub、导出和隐私设置 | 非日常流程 |

```text
│ ┌──────────────────────┐ │
│ │ 你与烟花与约定       │ │
│ │ 原文已保存 · 待整理  │ │
│ └──────────────────────┘ │
│                          │
│ 最近记录          查看全部│
│ ┌──────────────────────┐ │
│ │ 剧场版 链锯人 蕾塞篇│ │
```

交互规则：

- 次级入口进入影院特别放映记录。

- 最近记录卡片不展示评分、卡片数量或过多标签。
- 搜索页允许直接输入作品名，不要求浏览已有作品长列表。

```text
│ │      开始整理        │ │
│ └──────────────────────┘ │
│      只保存原文           │
└──────────────────────────┘
```

片名候选：

```text
电影名 *
┌────────────────────────┐
│ 穿越时空的少女         │
└────────────────────────┘
  穿越时空的少女
  時をかける少女 · 2006
  动画电影 · Bangumi      [选择]

  穿越时空的少女
  1983 · 真人电影          [选择]

  ＋ 就用当前输入新建
```

交互规则：

- 用户停止输入片刻后才显示候选，最多三条。
- 候选不遮挡原始感想框，也不强制选择。
- 选择电影院后，在地点按钮下方出现“粘贴电影票信息”。
- “更多信息”包含类型、观看日期、感想来源及外部链接，默认收起。
- “开始整理”与“只保存原文”都先确保本地草稿已经保存。
- 离线时主按钮改为“保存并等待联网整理”。

- 用户可以删除误识别的场次或修改片名、时间、影院、影厅、制式和座位。
- 脱敏结果只显示类型数量，不回显被移除的敏感值。

```text
┌──────────────────────────┐
│ ‹ 草稿      确认感想  1/5│
│                          │
│ 个人态度                  │
│                          │
│ [超喜欢] [喜欢] [无感]   │
│ [不喜欢] [不好说]        │
│                          │
│ AI 倾向：喜欢             │
│ “更被那份决心打动……”     │
│ 查看依据                  │
│                          │
│ ┌──────────────────────┐ │
│ │       确认并继续     │ │
│ └──────────────────────┘ │
│ 跳过本项                  │
└──────────────────────────┘
```

工作台采用五段式纵向流程，但允许从顶部进度入口跳转：

1. 个人态度；
2. 情绪反应；
3. 记忆卡片；
4. 观看场景与后续关系；
5. 推荐判断与预览。

### 9.1 情绪确认

```text
AI 建议
[感动 ×] [意外 ×] [可爱 ×] [有趣 ×]

＋ 添加情绪
查看原文依据
```

- 首先只展示 AI 建议。
- “添加情绪”进入分组选择；46 个标签不在主页面平铺。
- 标签可删除、自定义，允许一个都不选。

### 9.2 记忆卡片确认

```text
记忆卡片                         5 张

★ 哆啦A梦毁掉云之王国
  被击中的瞬间 · 感动
  因为王国本身很珍贵……      编辑

  小树苗成为外交大使
  系列联系 · 意外
  以前单元故事得到回应……    编辑

＋ 添加记忆卡片
```

- 卡片按核心记忆、原文顺序和相近主题排序。
- 支持编辑、删除、拖动排序、改变类型、关联场次和标记核心。
- 不显示“还缺多少项”，空白不被视为未完成。

### 9.3 后续关系和推荐

- 后续关系默认不自动选中；AI 建议显示为可点击的小提示。
- 推荐提供“会／看对象／不会”，但整项可以留空。
- AI 只能显示弱建议，不能预先选中按钮。

## 13. 移动端统一交互规则

### 13.1 草稿安全

- 输入时持续保存本地草稿；
- 页面切后台、浏览器关闭和短时断网后可恢复；
- 顶部或输入框下方以安静文案显示“已保存”，不频繁弹出提示；
- 同一草稿只保留一个明确的恢复入口，避免重复副本。

### 13.2 单手操作

- 每页主操作位于屏幕底部易触区域；
- 选择标签、态度和类型使用大触控区域；
- 不使用横向表格；
- 长文本编辑时不让固定按钮遮挡输入框。

### 13.3 信息减负

- 默认折叠没有 AI 内容的模块；
- 完整标签库和卡片类型库只在用户主动添加时出现；
- AI 证据默认收起；
- 不显示完成百分比，不暗示用户必须填满所有模块；
- “跳过”和“留空”是正常选择，不使用警告色。

### 13.4 AI 与用户边界

- AI 建议使用“AI 倾向”或“建议”文案；
- 用户未点击确认前，不使用已选中的视觉状态；
- AI 证据明确标识用户原话、引用他人、来源元数据和 AI 推测；
- 用户修改后的内容不被再次自动覆盖。

### 13.5 隐私

- 票务粘贴前说明本地脱敏；
- 脱敏确认只显示移除的数据类型，不显示敏感原值；
- GitHub 同步前显示目标仓库和写入路径；
- 保存、备份和公开发表始终是不同动作。

## 14. 原型验证任务

使用以下五条任务检查低保真原型：

### 任务 A：影院散场后快速写短评

使用《哆啦A梦：大雄与云之王国》样本：

- 目标：不整理排版即可开始；
- 检查：五项态度、少量情绪和 4–7 张卡片是否可在数分钟内确认；
- 失败信号：需要先填写大量作品或影院资料。

### 任务 B：极强烈的喜欢

使用《剧场版 链锯人 蕾塞篇》样本：

- 目标：保留高强度情绪和 Dolby Cinema 推荐；
- 检查：“超喜欢”“兴奋”“浪漫”和影厅建议不会被压缩为一个分数。

### 任务 C：明显不喜欢但仍有亮点

使用《你与烟花与约定》或《新·大雄的海底鬼岩城》样本：

- 目标：同时表达不喜欢、失望和角色／美术亮点；
- 检查：态度与正向卡片是否可以并存。

### 任务 D：一篇感想比较多种影院制式

使用《曼达洛人与古古》或《魔女宅急便》样本：

- 目标：一条感想关联多个场次；
- 检查：IMAX GT 与 ScreenX／Dolby 的比较不需要复制原文。

### 任务 E：影院 TV 动画先行上映

使用《二十世纪电气目录》前三话样本：

- 目标：通过次级入口记录作品名、第 1—3 话、影院活动和长篇发散感想；
- 检查：流程可以容纳该记录，但不会出现追番进度和逐集管理。

## 15. 原型通过标准

本低保真方案进入开发交接前，应满足：

- 普通电影记录入口始终最明显；
- 首屏没有超过两个必填输入项；
- 特别放映只增加一个低频入口和一个条件必填字段；
- 票务导入不会把邮件文字混入感想；
- 用户可以随时只保存原文；
- 46 个情绪标签和 44 个卡片类型均不在主流程平铺；
- 一条普通记录可在数分钟内完成确认；
- 多场次与特殊影院字段只在需要时展开；
- 保存、导出、GitHub 同步彼此分离；
- 整个原型不出现数字评分。
