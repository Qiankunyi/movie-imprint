# 电影印记：代表性验证集 v1

- 建立日期：2026-08-01
- 样本数量：12 条感想
- 构成：4 篇豆瓣文章、5 条 Bangumi 短评、3 条微博记录
- 用途：字段冻结、AI 边界验证、移动端原型验收
- 非用途：训练专属模型、评价文章质量、建立公开影评语料库

---

## 1. 样本处理原则

1. 本文档只保存来源链接、必要元数据和设计摘要，不复制四篇豆瓣文章全文。
2. 用户直接提供的 Bangumi 与微博原文可以用于内部验证，但在公开源码仓库发布前应移入私人验证数据或制作脱敏摘录。
3. 样本价值来自差异，不来自数量；12 条已经足够覆盖当前 MVP 的主要边界。
4. 新样本只有在能推翻现有字段、发现新边界或证明流程负担时才需要加入核心验证集。
5. AI 分析结果不能取代原文，也不能把引用他人的话归为用户本人观点。

## 3. 这批样本已经覆盖什么

## 3.1 总体态度

- 超喜欢：B05、D01、D03；
- 喜欢：D02、W03、B04；
- 无感：D04 的核心表达；
- 不喜欢：B01、B02；
- 不好说／复杂：B03、W02；
- 总体喜欢但存在重要遗憾：已由《魔女宅急便》案例覆盖。

现有五项个人态度仍然足够，不需要新增单选项。

## 3.2 情绪强度与文字长度

- B05 文字不长，却是情绪最强的样本之一；
- D04 字数较多，却主要表达“无感”；
- B01 很短，但同时有反感、困惑、失望和有限肯定；
- D02 较长，核心却由一个童年玩具记忆贯穿。

因此不能用字数决定卡片数量、分析深度或“长评模式”。系统只需要处理一段原文，不在产品中人为区分短评和长评。

## 3.3 电影与个人生活的连接

- 童年玩具记忆：D02；
- 京都留学与公共交通体验：W02；
- 家门口真实风景：B03；
- 对网络争论和后悔的自我反思：W01；
- 海边小镇生活向往：既有《魔女宅急便》案例；
- 创作与人生选择：D04。

“个人经历联想”不是边缘卡片，而是电影印记区别于普通影评工具的重要核心类型。

## 3.4 多次观看与影院制式

- IMAX 与 Dolby Cinema：既有《魔女宅急便》案例；
- IMAX GT 与 ScreenX：W03；
- 重映二刷的新发现：D03；
- 影院补看旧剧场版：B04；
- 特殊日期重映：W01。

Viewing Event 与 Imprint Record 分离的模型再次得到验证。

## 4. 新发现的 AI 边界

## 4.1 必须区分四种声音

一段感想中可能同时存在：

1. **用户直接感受：** 我喜欢、我无感、我被吓到；
2. **用户解释／推测：** 我觉得创作者可能疲惫、某段像是在表达什么；
3. **用户转述他人：** 朋友、Bangumi 用户、导演、原作者说过什么；
4. **来源平台元数据：** 力荐、推荐、发布日期、标签。

AI 不得把后面三种全部改写成“客观事实”。

## 4.2 证据需要记录声音来源

每段证据增加：

- `voice`：`user`、`quoted_other`、`source_metadata`；
- `claim_mode`：`direct_feeling`、`observation`、`interpretation`、`reported_statement`。

例如：

- “用户认为创作者疲惫”属于 `user + interpretation`；
- “原作者据说删除了发言”属于 `user + reported_statement`，不是已验证事实；
- 豆瓣“力荐”属于 `source_metadata`；
- 用户引用别人后明确说自己大体同意，引用与用户认同应分别记录。

## 4.3 不能过度客观化发散感想

D04 的价值不在于判断用户对创作者状态的分析是否正确，而在于保存：

- 用户为什么对这部作品无感；
- 用户如何把作品感受到的能量与旧作比较；
- 这种感受如何延伸到“做喜欢的事”这一人生判断。

记忆卡片可以主要是个人解释和生活观点，不需要强行补出剧情、角色、视听等“完整影评维度”。

## 5. 深度验证优先级

## 第一组：可能改变产品设计

1. **D04《EVA终》**：验证发散型感想、个人解释、几乎无正片内容；
2. **W02《二十世纪电气目录》**：决定影院 TV 动画先行上映是否进入范围；
3. **B01《你与烟花与约定》**：验证明确负面与有限亮点并存；
4. **B05《链锯人 蕾塞篇》**：验证强情绪、难以言说、明确制式推荐。

## 第二组：验证既有模型

5. **W03《曼达洛人与古古》**：多场次、多制式、真人电影；
6. **D03《蓦然回首》**：重映新发现与跨作品关系；
7. **D02《大白鲨》**：个人记忆、幕后信息和创作理解；
8. **W01《穿越时空的少女》**：影院效果、观众反应和个人共鸣。

## 第三组：回归检查

- D01、B02、B03、B04。

回归样本不必分别制作完整的数百行案例，只需在字段冻结后验证没有丢失关键内容。

## 6. 产品范围边界：影院中的 TV 动画先行上映

W02 不是电影，而是 TV 动画前三话的影院先行上映会。它同时满足：

- 观看体验发生在电影院；
- 有场次、观众、监督谈话和现场属性；
- 感想对象却是若干 TV 集数，而不是电影。

存在三种方案：

### 方案 A：严格排除

电影印记只接受电影。优点是边界最清楚；缺点是遗漏用户真实且重要的影院体验。

### 方案 B：完全扩展到 TV 动画

加入季度、集数、追番过程等字段。它会直接违背“电影版先跑通”的既定原则，不适合 MVP。

### 方案 C：影院特别放映的有限例外（建议）

MVP 仍不支持日常 TV 动画记录，但允许一种受限内容：

- 内容类型：`special_screening`；
- 活动类型：先行上映／多集连映／特别放映；
- 放映内容：作品名＋集数范围；
- 必须存在电影院或线下放映活动场景；
- 使用同一套原文、态度、情绪、记忆卡片和票务结构；
- 不加入季度追踪、逐集记录和在家观看 TV 动画。

方案 C 能保存现实需求，又不会把项目扩张成 TV 动画 Life OS。该方案需要用户最终确认后才能写入 MVP 边界。

## 7. 隐私与公开仓库

这些样本属于用户的个人表达。由于 `movie-imprint` 源码仓库计划公开：

- 公开产品文档可以保留作品名、来源链接和设计结论；
- 完整原文、完整结构化资产和带个人经历的详细案例应进入私有 `movie-imprint-records` 或专用私有测试数据；
- 公开测试夹具只使用短小、经过用户确认的摘录或人工合成文本；
- 票务案例只保留已经脱敏的结构字段。

当前工作区用于产品设计；公开仓库建立前必须执行一次样本隐私审计。
