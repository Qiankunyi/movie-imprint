## 目标

点「＋」后**不再直接弹出文本框**。先确定「看的是什么、在哪看的」，再进入书写。用户全程不需要输入任何 `#`。

---

## 新流程（三步）

```
Step 1 场景识别 → Step 2 确认 → Step 3 随手写
```

### Step 1 · 场景识别层

替换现有的「点＋直接进 composer」。新层结构：

```
┌─────────────────────────────────┐
│  ╭───────────────────────────╮  │  ← 剪贴板命中时才出现
│  │ 检测到票务信息 · 一键使用  │  │     （提案 A）
│  ╰───────────────────────────╯  │
│                                 │
│   ┌───────────────────────┐     │
│   │                       │     │  ← 大面积粘贴区，
│   │   粘贴票务信息         │     │     点击后聚焦、可直接长按粘贴
│   │                       │     │
│   └───────────────────────┘     │
│                                 │
│        没有票，直接写 →          │  ← 次要入口
└─────────────────────────────────┘
```

**为 W13 的截图 OCR 预留位置：** 粘贴区下方留一个次要入口的位置（本窗口**不实现**，也不显示占位按钮）。W13 会在这里加「从截图识别」，走本地 OCR（Tesseract.js，图片不出设备、不持久化）。R2 只需保证这块布局加一个次要入口时不用重排。

**剪贴板感知实现：**

- 打开层时尝试 `navigator.clipboard.readText()`
- 权限被拒或不支持 → 静默失败，不弹任何错误、不影响流程
- 判定「像票务文本」的启发式（全部在本地进行）：同时命中 ≥2 项即算命中
  - 含 `YYYY/MM/DD` 或 `YYYY年MM月DD日` 形式的日期
  - 含 `HH:MM` 形式的时间
  - 含影院关键词：`劇場` / `シネマ` / `シアター` / `TOHO` / `MOVIX` / `イオンシネマ` / `影院` / `Cinema`
  - 含票务关键词：`座席` / `スクリーン` / `上映` / `チケット` / `座位` / `场次`
- **命中后不自动解析**，只显示横幅。用户点了才走解析。避免误读剪贴板里的其他内容
- 横幅不展示剪贴板内容原文

### Step 2A · 票务确认卡（粘贴分支）

粘贴后：本地脱敏 → 解析 → 并发发起 Bangumi 匹配 → 展示确认卡。**这三件事都在后台，不设独立的「检查场次」页**（遵守 HANDOFF_V2 §2）。

确认卡一屏内容，一个「确认」按钮：

```
┌─────────────────────────────────┐
│ [海报]  《作品名》         [更换] │  ← 匹配中显示骨架；匹配失败显示解析出的片名
│                                 │
│  TOHO シネマズ 新宿              │
│  2026/08/03 (日) 19:20–22:00    │
│  IMAX · K-11, K-12 · 158分       │
│  ￥2,000                         │
│                                 │
│  ⟦舞台挨拶⟧ ⟦入場者特典⟧  [＋]    │  ← 活动标签，已解析的高亮，可增删
│  特典：第3週 色紙              │  ← 选了入場者特典才出现的自由文本
│                                 │
│  初看   [重看 · 第3次]           │  ← 系统按时间推定，点另一个即翻转
│                                 │  ← 与是否在影院无关；次数无上限
│  多场次时：卡片纵向堆叠，各自可改  │
│                                 │
│  姓名、邮箱、取票码已本地移除，   │  ← 隐私提示常驻
│  原始邮件不保存                  │
│                                 │
│           [ 确认 ]               │
└─────────────────────────────────┘
```

- 「更换」→ 展开最多三个 Bangumi 候选 + 一个「手动输入片名」
- 用户翻转初看／重看 → 给该 Event 打 `relation_locked: true`（R1 已约定不覆盖）
- 「确认」→ 生成 pending ViewingEvent，进 Step 3

**活动标签行（提案 I，本项目高频场景）：**

- R1 已从票务文本解析出 `event_types`，这里以**已选中**状态显示
- 点「＋」展开全部 11 种活动（`src/event-types.js` 的 `EVENT_TYPES`），多选，可取消误判
- 选中 `bonus_distribution`（入場者特典）→ 下方展开一个单行文本框填 `bonus_note`（如「第3週 色紙」）。特典内容每周不同，无法枚举，只能手填
- 没有解析到任何活动时，标签行**收起为一个「＋ 添加活动」小按钮**，不占版面
- 活动标签与制式徽章视觉上要能区分（制式=硬件规格，活动=这一场的性质），配色方案见 R3

### Step 2B · 场景二选一（跳过分支）

用户点「没有票，直接写」后，**不直接进书写**，先出现：

```
┌─────────────────────────────────┐
│  这次是在哪看的？                │
│                                 │
│  ┌──────────┐  ┌──────────┐     │
│  │ 在家／线上 │  │ 在影院    │     │
│  └──────────┘  └──────────┘     │
│                                 │
│  ── 点「在影院」后展开 ──         │
│  影院名  [____________]          │
│  制式    [2D ▾]                 │  ← 下拉：2D/IMAX/Dolby/4DX/MX4D/ScreenX/其他
│  活动    [＋ 添加活动]           │  ← 与 2A 相同的多选，默认收起
│                                 │
│  作品    [____________]          │  ← 必填，输入后即时向 Bangumi 匹配
│                                 │
│           [ 确认 ]               │
└─────────────────────────────────┘
```

- 「在家／线上」→ `location_type: "home"`、`source: "manual"`
- 「在影院」→ `location_type: "cinema"`、`source: "manual"`，影院名与制式写入 `viewing_context`
- 作品名输入框：输入 ≥2 字后 debounce 向 Bangumi 匹配，显示候选，可选可跳过
- 两条分支都可选初看／重看（该作品已有历史观影记录时才显示，否则默认 `first` 且不展示）

**⚠️ 初看／重看与观看地点无关。** 这两条分支的初看／重看逻辑**完全相同**，都由 R1 的 `assignViewingRelations` 按时间顺序推定。不要写「跳过 → 在家 → 默认 rewatch」这种捷径——用户完全可能先在家看，之后才去影院；也可能第一次记录的就是在家看。判定只看时间，不看地点。

### Step 3 · 书写层

复用现有 `composerOverlay`，改动：

- **顶部新增一行上下文条**（不可编辑，弱化灰字）：
  `《作品名》 · 2026/08/03 · TOHO 新宿 · IMAX`
  线上则：`《作品名》 · 2026/08/03 · 在家观看`
- 点上下文条可回到 Step 2 修改
- **placeholder 改掉**：现在是「用 # 标记作品，再写下看完后的想法」。改为「看完之后，先把还没消失的感觉写下来」。`#` 不再是必须的语法
- 工具栏移除票务按钮（票务已前移到 Step 1）；保留 `#` 按钮和列表按钮，`#` 降级为可选的强调手法
- 「完成」逻辑与自动保存、恢复行为**完全不变**

## 状态机

```
idle
 └─ open-capture ──→ capture:entry
       ├─ paste-ticket / use-clipboard ──→ capture:ticket-confirm ──→ capture:compose
       ├─ skip ──────────────────────────→ capture:scene-choice   ──→ capture:compose
       └─ close ─────────────────────────→ idle

capture:compose
       ├─ edit-context ──→ 回到 ticket-confirm 或 scene-choice
       ├─ finish ────────→ idle（记录已生成）
       └─ close ─────────→ idle（草稿保留，含 captureContext）
```

**草稿必须连同 `captureContext` 一起持久化。** 用户在 Step 3 关掉 App，再打开时应能从「继续写」直接回到 Step 3，而不是重走 Step 1。

## 测试要求

`tests/clipboard.test.mjs`：

- 真实票务文本 → 命中
- 普通中文段落 → 不命中
- 只含日期不含影院关键词 → 不命中（避免误报）
- 权限被拒 → 返回 `null`，不抛错

`tests/capture-flow.test.mjs`：

- 状态机各转移正确
- 粘贴分支：确认后 `pendingViewingEvent.location_type === "cinema"`、`source === "ticket_paste"`
- 跳过 → 在家：`location_type === "home"`、`source === "manual"`
- 跳过 → 在影院：`location_type === "cinema"`、`source === "manual"`，影院名与制式写入 `viewing_context`
- 用户翻转初看／重看 → `relation_locked === true`
- **该作品已有一次「在家」观影时，新记录一次「影院」观影 → 影院这次被推定为 `rewatch`**
- **该作品已有一次「影院」观影时，新记录一次时间更早的观影 → 新的成为 `first`，原有的变 `rewatch`**
- 该作品无历史记录时，初看／重看选择器不显示
- 解析出的 `event_types` 在确认卡预选；用户取消某一项后不再出现在最终 Event
- 手动添加活动 → 正确写入 `event_types`，去重
- 选中 `bonus_distribution` 才出现 `bonus_note` 输入；取消选中后 `bonus_note` 被清空
- 无活动时 `event_types` 为空数组（不是 `null`），标签行收起
- 草稿在 Step 3 中断后恢复，`captureContext` 完整
- **完成记录时，`rawText` 里没有任何自动插入的 `#`**

## 红线

- **不得**恢复独立的「检查场次」「AI 整理」「五步确认工作台」「最终预览保存」页面。Step 2 是一屏一按钮的确认卡，不是工作台
- 票务原文不持久化；隐私提示在确认卡常驻
- 原始感想先本地保存再联网
- Bangumi、AI 任一失败都不得阻塞记录完成
- 不使用紫色、紫色渐变、玻璃拟态
- 内部术语（RawLayer、Viewing Event、AI 工作台）不得出现在界面上
