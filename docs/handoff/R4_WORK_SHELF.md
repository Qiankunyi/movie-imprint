## 目标

除了首页的时间线，提供第二种组织方式：**按作品聚合**。同一部作品下挂靠多次观影与多条感想，并呈现跨次的评价变迁。

这是 R1 数据模型重构真正兑现价值的地方。

## 2. 作品书架

海报网格，每行 3 格（412 宽）或 2 格（360 宽）：

```
┌────┐ ┌────┐ ┌────┐
│海报│ │海报│ │海报│
│  ②│ │   │ │  ③│   ← 右下角角标：看过 N 次，N=1 时不显示
└────┘ └────┘ └────┘
 作品名  作品名  作品名
```

顶部筛选条（横向滚动的 chip）：

- 全部 / 动画电影 / 真人电影 / 活动 / 其他 / 未分类 （对应 `work.work_type`；迁移数据多为 `unspecified`，所以必须有「未分类」项）
- 追加一个 **「有活动场次」** 筛选：命中任何 `event_types` 非空的 ViewingEvent 的作品。舞台挨拶、特典这类场次是最值得回看的，值得一个独立入口
- 排序：最近观看（默认）/ 观看次数 / 首次记录时间

注意：`work_type: "event"`（作品本身就是活动，如 Live Viewing 演唱会）与「有活动场次」（普通电影的舞台挨拶场）是两回事，筛选项不要混用。

无海报的作品用占位块，与 R3 保持一致的处理。

## 3. 作品页

```
┌──────────────────────────────────┐
│  ╱  大海报（顶部背景，带渐变遮罩）  ╱ │
│                                  │
│  《作品名》                        │
│  2026 · 动画电影 · Bangumi ↗      │
│  日本上映 08/01 · 中国上映 [＋填写] │
│                                  │
│ ── 观影履历 ──────────────────    │
│ ① 2026/08/03  初看                │
│    TOHO シネマズ 新宿             │
│    IMAX · K-11, K-12 · 158分      │
│    ￥2,000                        │
│    ⟨舞台挨拶⟩ ⟨入場者特典⟩         │
│    特典：第3週 色紙               │
│                                  │
│ ② 2026/11/20  重看                │
│    在家观看                       │
│                                  │
│ ── 评价变迁 ──────────────────    │
│    喜欢 ─→ 超喜欢 ─→ 超喜欢       │  ← N 条记录 N 个节点，无上限
│                                  │
│ ── 感想 ────────────────────     │
│ · 2026/08/03  影院观看后 · 3 张卡片 │
│ · 2026/11/20  重看 · 1 张卡片      │
│ · 2029/03/02  补充记录            │
│                                  │
│         [ ＋ 补充记录 ]           │
└──────────────────────────────────┘
```

### 3.1 观影履历

按时间升序。影院场次显示完整信息（影院、制式、座位、时长、票价、**活动徽章与特典备注**）；线上场次只显示日期与「在家观看」。

**初看／重看的标注只反映时间顺序，与地点无关。** 履历里完全可能出现「① 在家 · 初看 → ② 影院 · 重看」——用户先在家看过，之后趁重映去了影院。渲染时直接读 `viewing_relation` 与 `watch_index`，不要根据 `location_type` 推断任何东西。观看次数无上限，履历要能正常渲染 7 次、10 次。

**`relation_conflict: true` 的事件**（用户手动锁定的初看／重看与时间顺序矛盾，见 R1）：在该行下方显示一行温和提示，如「这次被标为初看，但时间上不是最早的一次」，附「改回按时间判断」与「保持我的选择」两个按钮。**默认保持用户的选择**，系统不擅自覆盖。

**每一行都要有「编辑」入口**，可改地点、时间、影院、制式、活动、初看／重看。改完后触发该 work 全部事件重排（R1 已实现）。用户补录一次很久以前的观看，就是从这里进的。

**活动在作品页要完整显示，不做首页那样的数量截断**——作品页是回看细节的地方，四个活动就显示四个。`bonus_note` 显示在活动徽章下方一行。这些信息也可在此处直接编辑（复用 R2 的活动多选组件）。

`needs_review: true` 的 Event（R1 迁移补建的）显示一行提示：「这次观看的场景待确认」+ 一个「补充信息」按钮，点开可选在家／影院并手填。

### 3.1b 上映日期（为 W14 纪念日功能服务）

标题下方一行显示 `release_dates`：

- `jp` 由 R1 从 Bangumi 自动写入，只读显示；无值时不显示该项
- `cn` Bangumi 一般没有，提供**手动填写入口**（点「＋填写」弹一个日期输入）
- 两者都为空 → 整行不显示，不要留一行空标签

这一行看起来是装饰，实际是 W14「首映纪念日」的唯一数据入口。填过的作品以后才会在周年当天触发庆祝。

### 3.2 评价变迁（提案 D · 本窗口的核心交付）

同一作品下按时间排列各条 Record 的 `attitude`：

- 只有一条记录 → **不显示这个区块**（没有"变迁"可言）
- 两条以上 → 横向箭头链，态度值不同的地方加视觉强调
- 态度为空的记录跳过，不显示为"无"
- **节点数无上限**，链条按记录时间排列；超过屏宽时横向可滚动，不要截断或折叠成"…"
- **节点标注用日期，不用「初看／重看」**——补充记录（supplement）也在这条链上，而它根本没有观影事件，标"重看"是错的
- 不做任何解读或评语，只呈现事实。**AI 不参与这个区块。**

### 3.3 感想列表

每条一行：日期 + 类型标签（影院观看后 / 重看 / 补充记录）+ 卡片数量。点击进入现有的感想详情页。

### 3.4 补充记录入口（提案 E）

「＋ 补充记录」→ 直接进入书写层（复用 R2 的 Step 3），上下文条显示：

```
《作品名》 · 补充记录 · 距首次观看 3 年
```

生成的 Record：

```js
{
  work_id: <该作品>,
  viewing_event_id: null,
  record_kind: "supplement"
}
```

**不创建 ViewingEvent。** 这是补充记录与观影记录的根本区别。

## 4. 路由

现有 `state.view` 是 `home` / `detail` 二值。扩展为：

- `home`（时间线）
- `shelf`（作品书架）
- `work`（作品页，带 `state.currentWorkId`）
- `detail`（感想详情）

返回路径：`detail` ← `work` ← `shelf` ← `home`，以及 `detail` ← `home`（从时间线进入时）。
需要记住来路，返回时回到正确的上一级并**保持滚动位置**（首页已有 `state.returnScrollY` 机制，书架与作品页要各自维护）。

## 6. 测试要求

`tests/work-view.test.mjs`：

- 一个 work + 2 个 event + 3 条 record（含 1 条 supplement）→ 履历 2 项、感想 3 项
- 只有 1 条 record → `attitudeTimeline` 为空数组（触发不显示）
- **在家 `first` + 影院 `rewatch` 的履历顺序与标注正确**，不因影院而颠倒
- **7 个 event → 履历 7 项，`watch_index` 1..7 完整**
- `relation_conflict: true` 的事件被标出，供 UI 显示提示
- `attitudeTimeline` 节点用日期标注，supplement 记录也在链上且不带「重看」字样
- 态度为空的 record 不进 `attitudeTimeline`
- `stats.totalMinutes` / `stats.totalSpent` 正确累加，缺值不计入且不产生 `NaN`
- `stats.eventTypeCounts`：两场都有舞台挨拶 → `{stage_greeting: 2}`；无活动 → 空对象
- 作品页显示全部活动徽章，不做首页的 2 个截断
- supplement record 不产生 ViewingEvent
- `merged_from` 里的旧 work id 也能查到该 work（R1 已提供 `db.getWorkById`）

`tests/routing.test.mjs`：

- 四个视图的进入与返回
- 从时间线进详情 → 返回时间线；从作品页进详情 → 返回作品页
- 滚动位置各自保持

## 7. 验收条件

- [ ] 同一部电影记录三次（一次影院 / 一次在家 / 一条作品页补充），书架里**只有一个条目**，角标显示「3」（感想数）或「2」（观看数，二选一后统一）
- [ ] 作品页显示 2 次观影履历、3 条感想、1 条评价变迁链
- [ ] 只看过一次的作品，作品页不显示「评价变迁」区块
- [ ] **在家初看 + 影院重看**的作品，履历标注正确（在家那行是初看）
- [ ] 观看 7 次的作品，履历与评价变迁链都完整渲染，360 宽下可横向滚动不错乱
- [ ] 履历每行可编辑；改时间后该作品全部事件重排，页面即时反映
- [ ] `relation_conflict` 的提示出现，且默认保持用户的选择
- [ ] 从作品页发起补充记录，生成的 record `viewing_event_id` 为 null、`record_kind` 为 `supplement`，且**没有新增 ViewingEvent**

- [ ] 「有活动场次」筛选可用，且与 `work_type: "event"` 区分正确

## 红线

- 作品页不是字段清单。已有的完整字段不必全部铺开——票价、座位放在履历行内，卡片内容不在作品页展开
- 评价变迁只呈现事实，不做 AI 解读
- 不使用紫色、紫色渐变、玻璃拟态
- 补充记录**不得**自动创建 ViewingEvent
- 内部术语不进界面
