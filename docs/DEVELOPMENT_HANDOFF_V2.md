## 2. 已确认的产品原则

- 开发文档描述系统需要实现的能力，不代表所有字段都应同时显示；
- 默认台前只有记录、阅读和必要时纠错；解析、匹配、AI、保存和同步尽量在后台；
- 隐藏、后移、合并页面不等于删除功能；MVP 功能应尽量完整实现；
- “原始感想”、RawLayer、Viewing Event、AI 工作台等内部术语不得进入普通界面；
- 不得恢复独立“检查场次”“AI 整理”“五步确认工作台”“最终预览保存”等默认主流程页面；
- 不得使用紫色、紫色渐变、玻璃拟态和通用 AI SaaS 模板。

## 3. 当前六个关键状态

1. 首次使用：二次元电影视觉＋底部“＋”；
2. 日常记录流：已记录作品按日壁纸＋内容卡片＋底部“＋”；
3. 随手记录：当前页面压暗，输入层与系统键盘相接；
4. 票务粘贴：粘贴后自动脱敏、解析并进入后台，不设检查场次页；
5. 个人态度与推荐：态度可显示文字倾向，推荐必须由用户独立选择；
6. 成品与记忆卡片：完整单卡分页，直接编辑／添加，并提供导出与同步。

样张入口：`docs/design/revision-02/renders/contact-sheet-*.png`。

## 4. 下一窗口的第一目标：可操作纵向切片

不要先批量搭空页面。先实现并在 Android 尺寸浏览器上验证：

```text
首页记录流
  → 点击底部“＋”
  → 输入层升起并获得真实文本焦点／系统键盘
  → 输入含 #作品名 的文字
  → IndexedDB 即时保存与恢复
  → 点击右下角“完成”
  → 回到原滚动位置
  → 记录卡原位出现
  → 打开成品详情
  → 修改个人态度与推荐
  → 查看／编辑／新增一张记忆卡片
```

这一切片先使用本地假数据和确定性假分析，不接真实 AI、GitHub 或私人票务数据。目标是验证手机交互、状态边界、数据不丢失和视觉落地。

## 5. 第一目标的验收条件

- 412×915 与 360×800 均可单手完成主路径；
- 键盘出现时不遮挡工具栏、右下角“完成”和当前输入行；
- 关闭、切后台、刷新后文字可恢复；
- `#` 标签保留在原文中，同时生成可解析的本地候选；
- 首页壁纸不会压过文字，蒙版主体与顶部安全层使用独立 token；
- 记录卡和成品详情不是字段清单；
- 记忆卡片一次完整显示一张，不截断下一张；
- 推荐值默认空，只能由用户选择；态度、推荐和后续行为互不推导；
- 不需要网络也能完成记录与回看；
- 至少具备组件、状态、数据恢复与移动尺寸测试。

## 6. 后续实施阶段

### C1 本地可靠记录

- PWA 壳、访问保护占位、IndexedDB schema 与迁移；
- 首页、记录层、本地草稿、只保存文字、成品详情；
- 离线与恢复；
- 不接真实外部服务。

### C2 作品匹配与壁纸

- Bangumi 搜索代理、最多三个候选、稳定 subject ID；
- 官方条目图片接口、缓存、按日期稳定轮换、换一张／固定／关闭；
- 首次使用、断网、无图时回退原创二次元视觉；
- 不抓取 Bangumi 页面。

### C3 AI 结构化整理

- 服务端 AI 代理；原文先本地保存；
- 态度、情绪和有证据的记忆卡片；
- 推荐值不得由 AI 推断；用户选择后，AI 才可协助整理条件字段；
- 失败、重试和只保存文字路径。

### C4 票务与场次

- 票务文本与感想文本严格隔离；
- 本地拆分和脱敏后才可进一步处理；
- 粘贴即导入，不增加中间检查页；
- 成果页自然呈现场次，错误在那里修改；
- 用 SMT 双邮件案例验证多场次和敏感信息移除。

### C5 完整结构编辑

- 46 种情绪标签、44 种卡片类型及自定义类型；
- 卡片编辑、删除、排序、改类型、关联场次、标记核心；
- 初看、重看、后续补充、多场次关系；
- 观看场景、后续关系、推荐条件字段；
- 所有复杂能力通过成果页和按需层进入。

### C6 导出与 GitHub

- 同一正式数据生成 JSON、Markdown、TXT 和全部导出；
- 用户主动同步 GitHub；同步前显示仓库、分支和路径；
- 同步失败不影响本地记录；
- 私人数据仓库与公开源码仓库分离；
- 不自动公开发布，不实现复杂双向合并。

## 7. 壁纸实现约束

- 从已有且具有 Bangumi subject ID 的记录中选择候选；
- 使用本地日期＋候选 ID 生成稳定日选结果，同一天不因重启变化；
- 壁纸主体和顶部导航分别使用 `--wallpaper-scrim`、`--wallpaper-header-scrim`；
- 当前设计起点：浅色主体约 48%、深色主体约 56%，顶部约 70%；实际图片差异较大，需做文字对比兜底；
- 记录卡保持不透明；不能对整页施加厚重白雾；
- 缓存设置容量和过期策略，断网使用缓存；
- 无记录、无图或失败时使用内置原创二次元视觉。

## 8. 推荐判断约束

- 选项固定为会／看对象／不会，整项可空，不增加第四项；
- AI 不提供推荐倾向，不预选，也不由个人态度推导；
- 会：推荐理由、注意事项、可选推荐对象；
- 看对象：推荐给谁、推荐理由、注意事项；
- 不会：不推荐原因、作品问题／个人不适合、仍值得肯定之处；
- 只在用户选中后展开相应条件字段；成果页以自然语言摘要呈现；
- 后续补充默认不要求重新判断，用户主动修改时才展开。

## 9. 数据与安全红线

- 原始感想先保存再联网；
- 票务原文默认不持久化，不进入感想 AI、日志、导出或 GitHub；
- 姓名、邮箱、手机号、订单号、取票码、二维码令牌、票价和支付信息默认移除；
- 密钥与令牌不进入前端、日志、导出和仓库；
- AI、Bangumi、GitHub 任一失败均不得造成原文丢失；
- 不使用私人验证原文填充公开截图、测试夹具或公开仓库。
