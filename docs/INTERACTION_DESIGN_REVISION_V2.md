# 电影印记：以记录为中心的交互修订 v2

状态：视觉样张前置交互基准  
日期：2026-08-01  
适用范围：MVP 移动端台前体验

## 1. 修订目的与覆盖关系

产品定义、字段冻结稿继续决定系统需要保存的数据；本文件决定这些数据何时、以何种方式出现在用户面前。

当本文件与 `MOBILE_LOW_FIDELITY_PROTOTYPE_V1.md` 的页面划分冲突时，移动端台前交互以本文件为准。数据结构、隐私与原文安全规则不变。

核心修订：不再把后台处理管线逐步翻译成页面。系统内部可以经历识别、脱敏、匹配、整理和同步；用户主流程只感受到记录、阅读和必要时纠错。

## 2. 三层产品模型

### 2.1 台前：用户真正要做的事

- 随手写下刚看完电影后的想法；
- 回看过去的记录；
- 阅读系统整理出的记忆卡片；
- 在成品中发现错误时直接修正。

### 2.2 按需出现：有具体原因才打扰用户

- 粘贴票务邮件；
- 作品识别歧义；
- 选择个人态度；
- 修改已呈现的场次、标签或卡片；
- 重新整理失败的内容。

### 2.3 台面下：系统自动完成

- 本地即时保存和恢复；
- 从 `#作品名`、正文和上下文识别作品；
- 从 `#电影院` 判断是否提示票务导入；
- 票务文本的本地拆分、脱敏和结构化；
- AI 态度建议、情绪提取和记忆卡片生成；
- 作品、场次与感想之间的关联；
- 正式数据保存、导出和同步队列。

“原始感想”“RawLayer”“Viewing Event”“AI 工作台”等内部术语不得直接作为普通界面标题。

## 3. 主路径

```text
首页记录流
  → 点击底部“＋”
  → 当前页面压暗，记录层从键盘上方升起
  → 直接输入，可用 # 写作品名和电影院
  → 自动保存在本机
  → 收起记录层，回到原位置
  → 后台识别与整理，卡片原位更新状态
  → 打开成品阅读；需要时才修改
```

主路径不出现电影名必填框、观看地点选择器、“开始整理”“只保存原文”或逐页最终预览。

## 4. 六个关键评审状态

六个样张是使用状态，不是六张后台表单。

### S1 首次使用：首页空状态

- 大面积二次元电影／动画氛围视觉建立产品印象；
- 界面只有安静的产品名称和底部拇指可及的“＋”；
- 不展示草稿、最近记录、统计和功能说明；
- 尚无个人记录时使用应用内置的原创二次元电影视觉，不冒充任何作品海报；
- 点击“＋”立即进入 S3。

### S2 日常使用：首页记录流

- 已完成或待整理的记录本身构成页面主体；
- 从已经记录且具有 Bangumi 条目 ID 的作品中按日选取一部，读取并缓存其条目图片作为当日壁纸；
- 同一天保持稳定，不在每次启动时随机跳变；允许以后在二级菜单中“换一张、固定、关闭”，但不把控制项放在首页；
- 壁纸始终位于内容层之下，使用固定蒙版控制对比；记录卡、文字和主操作必须比壁纸更突出；
- 每条记录是可阅读的内容卡片，不是字段摘要行；
- 顶部只保留导航与搜索；
- “＋”持续悬浮在底部拇指区；
- 草稿不设独立模块，直接以记录卡片状态出现；
- 搜索、筛选和导入历史票务进入二级菜单。

### S3 捕捉当下：键盘上的记录层

- 不跳转新页面；背景记录流保留并压暗；
- 底部记录层与系统键盘直接相接；
- 键盘上方的整块空白面都是编辑区域，不绘制表单边框；
- 未输入时仅显示一句会消失的引导语；
- 引导语需要说明内容和 `#` 的作用，例如“用 # 标记作品，再写下看完后的想法”；可再显示一行较弱的示例；
- 工具栏位于编辑区底部，只显示 `#`、列表、票务入口和明确标注的“完成”动作；列表只插入有序／无序纯文本前缀，不把原始感想改成富文本；不提供无用途的图片插入；
- “完成”位于输入区域右下角、键盘上方，不进入系统键盘区域，也不使用含义不明的单独勾号；
- 输入即本地保存，保存状态不抢占注意力；
- `#穿越时空的少女` 表达作品，`#电影院` 表达影院观看；未写后者时不追问场次。

### S4 票务粘贴：条件出现的输入层

- 仅在用户主动点击票务入口，或已经表达 `#电影院` 后选择补充时出现；
- 仍是当前上下文上的底部层，不进入“检查场次”页面；
- 提供一个大文本区域与一个“导入”动作；
- 点击后自动在本机脱敏、解析并写入后台；成功只给轻量反馈；
- 不展示中间解析表格，也不要求逐项确认和编辑；
- 完全无法识别时说明未导入，不影响感想草稿；
- 解析结果以后在记录详情中自然呈现，用户在那里按内容修改。

### S5 个人态度与推荐：相邻呈现、独立决定

- 态度不是五个等规格按钮；
- `不喜欢 → 无感 → 喜欢 → 超喜欢` 形成有方向的心理轴，位置、大小和反馈共同表达程度；
- `不好说` 是复杂与矛盾，不是轴的最右端，必须作为独立分支呈现；
- AI 建议只作为低权重提示，不预先替用户选中；
- 提示保持简短，例如“文字倾向：喜欢”，不解释产品如何尊重用户选择；
- 同一层下半部询问“会推荐给别人吗？”，提供“会／看对象／不会”三个选择；整项可以留空，不增加第四个“暂不判断”；
- 推荐值不显示 AI 倾向，也不从态度或正文自动选中；用户必须亲自选择；
- 选择后只展开对应的条件内容：“会”显示理由、注意事项和可选对象；“看对象”显示对象、理由和注意事项；“不会”显示原因、作品问题／个人不适合和仍值得肯定之处；
- 条件内容先以一至两行摘要出现，点击后进入编辑层，不在当前页面铺开全部字段；
- 允许跳过并只保存文字；结构化成品需要时再提示完成；
- 选择后直接返回成品，不进入五步工作台。

### S6 成品阅读：详情与记忆卡片

- 取消独立“最终预览”页面；成品详情本身就是结果；
- 第一屏先呈现作品、日期与用户文字，而不是字段清单；
- 场次压缩成一行自然语言，例如“7 月 18 日 · MOVIX 京都 · Dolby Cinema”；
- 记忆卡片使用真正的卡片阅读方式：一次完整显示一张，通过分页或手势切换，不用截断下一张暗示滑动；
- 单张卡片只展示类型、标题和一段内容，证据、关联场次、改类型等进入卡片菜单；
- 成果页直接提供编辑当前卡片与添加新卡片的入口；完整类型库仍在新增／改类型时出现；
- 情绪和态度作为阅读线索，不占据独立表单模块；
- 修改入口依附在对应内容或溢出菜单中，不让整页保持编辑态；
- 保存是背景状态，不放大型“保存正式记录”按钮；
- 成果页提供“导出与同步”入口，完整支持 Markdown、JSON、TXT、全部导出和用户主动同步 GitHub。

## 5. 原页面的处理决定

| v1 页面／模块 | v2 决定 | 台前替代 |
|---|---|---|
| 新建电影记录页 | 取消 | 首页上的底部记录层 |
| 观看地点四选一 | 取消 | 自然文本与 `#电影院`；未表达则不追问 |
| 票务确认／检查场次 | 取消 | 粘贴即导入；结果在详情中可改 |
| AI 整理状态页 | 取消 | 首页卡片上的安静状态；可离开 |
| 五步确认工作台 | 拆除 | 只在需要时呈现单一判断层 |
| 记忆卡片类型库主入口 | 降级但完整保留 | 新增卡片或修改卡片类型时的二级选择器 |
| 最终预览与保存页 | 取消 | 成品详情即时呈现并自动保存 |
| 草稿箱首页模块 | 取消 | 草稿作为记录流中的一种状态 |

## 6. 信息显露规则

每个元素出现前必须满足至少一个条件：

1. 用户此刻需要据此作决定；
2. 用户刚刚主动请求该能力；
3. 系统无法安全继续，必须由用户补充；
4. 信息本身就是用户要阅读的成品。

仅仅“数据库中存在该字段”不是显示理由。

## 7. 交互与可用性约束

- 单一主操作位于底部拇指舒适区；
- 常用触控目标至少 48dp；
- 编辑状态按“键盘已经出现”设计，而非事后避让键盘；
- 正文默认 17sp／28sp 左右，中文和日文长文本优先；
- 颜色不是唯一的状态和态度编码；
- 不因 AI 处理而阻塞返回首页；
- 任何网络或解析失败都不得丢失已输入文字；
- 空白不是未完成，不以完整字段覆盖率评价一条记忆。

## 8. 功能完整性约束

简化台前信息不等于删减产品功能。`DEVELOPMENT_HANDOFF_V1.md`、`PRODUCT_DEFINITION_MVP_V1.md` 与字段冻结稿中的 MVP 功能仍应尽量全部实现。

| 功能需求 | 默认界面 | 完整入口／后台位置 |
|---|---|---|
| 作品匹配与稳定 ID | 输入后不打断 | 后台匹配；歧义时在记录卡或成果页提示 |
| 自动保存、离线恢复 | 不显示常驻模块 | 本地草稿与 outbox；失败时才提升提示 |
| 票务拆分、脱敏、多场次 | 一个粘贴层 | 后台处理；成果页按场次编辑 |
| 个人态度、情绪、推荐 | 态度与推荐合并为相邻选择；成果页作为阅读线索 | 条件字段在选择后的二级编辑层完整提供；推荐值不由 AI 推断 |
| 44 种记忆卡片类型 | 不在主流程铺开 | 新增／改类型时进入完整类型库 |
| 卡片编辑、删除、排序、核心、关联场次 | 当前卡片只露出编辑 | 卡片编辑层与溢出菜单完整提供 |
| 后续关系、重看与多场次关联 | 成果页自然呈现 | 对应内容编辑层完整提供 |
| Markdown／JSON／TXT | 成果页导出入口 | 导出面板支持单项和全部 |
| GitHub 主动同步、状态与失败恢复 | 成果页导出入口 | 同步面板与后台队列；绝不静默发布 |

页面可以合并、功能可以后移，但不得因静态样张没有同时展示，就从实施范围中删除。

## 9. 壁纸数据规则

- 优先使用已经保存的 Bangumi `subject_id`，通过当前官方条目图片接口读取封面；不抓取 Bangumi 页面；
- 按本地日期与候选条目 ID 生成稳定选择，同一天默认不变化；
- 原图在本地缓存并记录来源，断网时使用最近缓存；
- 图片加载失败、条目无图或首次使用时回退到内置原创视觉；
- 壁纸只作为低层氛围，不参与内容语义，不影响文字对比；
- API 使用遵守 Bangumi 的 User-Agent、缓存与访问频率要求；实现阶段再次核对接口许可与图片使用边界。

## 10. 后续验证问题

静态样张只验证层级、密度和视觉方向。进入前端前仍需用可点击原型验证：

- 键盘弹出后实际可写高度是否足够；
- 记录层收起、恢复和误触退出是否安心；
- 态度心理轴能否无需说明被理解；
- 横向记忆卡片是否比纵向清单更适合回看；
- 长文、多个场次与日文长标题是否仍保持清晰。
