# ADR-001：将“/”作为可选系列速记，而非正式标签层级

日期：2026-08-01  
状态：已采纳

## 背景

用户可能自然地写出 `#哆啦A梦/大雄与动物行星`，希望快速表达“这部作品属于哆啦A梦系列”。flomo 也使用 `/` 创建多级标签，并让上级标签成为浏览入口。

电影印记与通用笔记工具的核心差异是：作品最终会落到稳定的 `Work` 实体，并通过外部作品 ID、别名与人工修正确认身份。系列关系可能多对多，也可能同时包含系列、世界观、重拍、衍生与跨界作品，不能可靠地压缩成唯一树状路径。

## 决策

1. 支持 `#系列/作品`，也允许 `#上级/子系列/作品`，但只把它解释为用户输入的匹配线索。
2. 原始文字与完整标签保持不变，不自动把 `/` 改成冒号，也不提前创建新的正式作品或系列实体。
3. 解析结果包含：
   - `seriesPath`：最后一段之前的全部上级线索；
   - `workTitleHint`：最后一段作品线索；
   - 原标签：继续作为可追溯的用户原始输入保存。
4. 记录层即时显示“待匹配确认”的识别反馈，但 `/` 不是必填语法，普通的 `#作品名` 仍是默认入口。
5. 下一阶段作品匹配可以同时使用完整标签、系列线索与作品线索召回候选；最终标题、作品 ID 与系列归属以匹配结果或用户确认结果为准。

## 原因

- 保留 flomo 式速记的低输入成本和可理解性；
- 不让用户为了分类而打断“先写下来”的主流程；
- 避免把影视作品复杂、可变化的多重关系固化成单一目录树；
- 避免把标题本身含 `/` 的作品直接当作已确认的系列关系；匹配器可以纠正这类歧义；
- 与既有的稳定 `Work` 身份、作品别名和“系列联系”记忆卡片保持职责分离。

## 非目标

- 当前不实现全局标签树、父标签聚合页或层级标签管理器；
- 当前不新增正式 `Series` 顶层实体；
- 当前不根据斜线线索自动合并作品。

## 验收例

- 输入 `#哆啦A梦/大雄与动物行星`：原文不变，提示“哆啦A梦 → 大雄与动物行星”。
- 输入 `#穿越时空的少女`：行为与当前版本一致，不显示系列提示。
- 输入标题本身含 `/` 的作品：允许先产生待确认线索，但正式匹配结果可以将其识别为单一标题。
