## 一、卡片设计原则（`PRODUCT_DEFINITION_MVP_V1.md` §5.1）

记忆卡片是"电影印记"的核心结构，不是要求全部回答的问卷。

- AI 根据原文只生成实际有内容的卡片。
- 用户新增卡片时先选类型，再看提示。
- 每张卡片只表达一个主要记忆点；同一类型可以有多张。
- 所有提示字段均可留空，但一张正式卡片至少需要"内容"。
- 卡片类型可以修改，不必删除重建。
- 用户可以删除错误卡片、调整顺序、标记"核心记忆"。
- 卡片不追求互斥；一个片段同时涉及场景和主题时，选择更接近用户记忆重点的主类型，并通过关联标签补充。

## 二、卡片通用结构（`PRODUCT_DEFINITION_MVP_V1.md` §5.2，与 `FIELD_AND_TAXONOMY_FREEZE_V1.md` §7 一致）

| 字段 | 必填 | 说明 |
|---|---:|---|
| `card_id` | 是 | 稳定 ID |
| `type` | 是 | 预设或自定义类型 |
| `title` | 否 | 便于浏览的短标题，可由 AI 建议 |
| `content` | 是 | 记住了什么 |
| `why_it_matters` | 否 | 为什么记住、为什么对自己重要 |
| `related_emotions` | 否 | 关联已有情绪标签 |
| `linked_viewing_ids` | 否 | 卡片只针对某次或用于比较多次观看时，关联相应场次 |
| `evidence` | 否 | 原始感想中的依据；AI 卡片原则上必须有 |
| `is_core` | 是 | 是否为本次记录的核心记忆，默认否 |
| `order` | 是 | 用户确认后的显示顺序 |
| `provenance` | 是 | AI 建议、用户接受／修改／新增 |
| `custom_fields` | 否 | 类型模板的补充字段 |

证据字段（evidence）固定包含（`FIELD_AND_TAXONOMY_FREEZE_V1.md` §7）：`excerpt`（原文短片段）、`basis`（明示／推测）、`voice`（用户／引用他人／来源元数据）、`claim_mode`（直接感受／观察／解释／转述）、`explanation`、`confidence`。

## 三、44 种记忆卡片类型库（`PRODUCT_DEFINITION_MVP_V1.md` §5.3，逐条带模板提示）

### A. 故事与表达
| 类型 | 适用内容 | 模板提示 |
|---|---|---|
| 场景 | 一段具体发生的内容 | 发生了什么？为什么记住？ |
| 台词 | 对白、独白或字幕文字 | 台词是什么？谁说的？当时发生了什么？ |
| 剧情转折 | 改变故事方向的节点 | 转折是什么？带来了怎样的理解或情绪变化？ |
| 结局 | 对结尾的感受和理解 | 结局发生了什么？满意、意外还是遗憾？ |
| 主题 | 作品反复触及的核心命题 | 作品在讨论什么？它如何触动了自己？ |
| 观点／表达 | 某个具体立场、判断或表达方式 | 认同、反对还是觉得复杂？为什么？ |
| 设定／世界观 | 规则、背景和世界构造 | 哪个设定最有记忆点？它怎样影响故事？ |
| 改编处理 | （§6.1 冻结清单新增，未在 §5.3 展开模板） | — |

### B. 人物与表演
| 类型 | 适用内容 | 模板提示 |
|---|---|---|
| 角色 | 对单个角色的记忆 | 记住了谁？哪个行为或特质最突出？ |
| 人物关系 | 两人或多人之间的关系 | 关系如何变化？哪个互动最难忘？ |
| 真人表演 | 演员的动作、神态、台词处理 | 哪位演员？具体哪里打动或影响了观看？ |
| 配音 | 声优或配音表现 | 哪个声音、语气或片段最突出？ |

### C. 视觉与演出
| 类型 | 适用内容 | 模板提示 |
|---|---|---|
| 作画／动画表现 | 动画动作、变形、节奏和细节 | 哪个片段？动作或画面为什么突出？ |
| 镜头／摄影 | 构图、机位、运动、焦段等 | 哪个镜头？它如何改变了感受？ |
| 演出／调度 | 画面、节奏、人物和空间的组织 | 怎样安排信息或情绪？ |
| 美术／场景设计 | 背景、空间、建筑、道具 | 哪个空间或设计留下印象？ |
| 色彩／光影 | 色彩方案和光线变化 | 哪种色彩或光影？产生了什么效果？ |
| 剪辑／节奏 | 镜头连接和叙事节奏 | 哪一段节奏特别有效或令人不适？ |
| 视效／特效 | CG、合成、实拍特效等 | 哪种效果？服务了体验还是造成干扰？ |

### D. 声音与音乐
| 类型 | 适用内容 | 模板提示 |
|---|---|---|
| 配乐 | 场景内外的音乐 | 哪段音乐？与画面和情绪怎样结合？ |
| 歌曲 | 主题曲、插曲、片尾曲 | 哪首歌、出现在哪里、为什么记住？ |
| 音效 | 环境声、动作声和特殊声音设计 | 哪个声音最明显？带来了什么体验？ |
| 声音演出 | 静默、声场、声音切换等整体设计 | 声音如何组织注意力或情绪？ |

### E. 个人反应
| 类型 | 适用内容 | 模板提示 |
|---|---|---|
| 被击中的瞬间 | 最直接触动自己的点 | 是哪一刻？为什么像是对自己说话？ |
| 可爱／有趣的点 | 不必承担主题意义的小瞬间 | 什么让自己笑、觉得可爱或想反复回看？ |
| 不适／反感 | 排斥、冒犯或身体性不适 | 不适来自什么？是表达、内容还是个人边界？ |
| 遗憾／不满 | 没有达到期待的部分 | 希望怎样处理？它影响了整体体验吗？ |
| 疑问／困惑 | 没看懂或仍想追问的地方 | 问题是什么？是信息缺失还是表达复杂？ |
| 惊喜／意外 | 超出预期的内容 | 原本预期是什么？实际发生了什么？ |
| 最想长期记住 | 主动指定的长期记忆 | 如果以后只记得一个点，希望是什么？ |
| 个人感悟 | （§6.5 冻结清单新增，未在 §5.3 展开模板） | — |

### F. 关联与语境
| 类型 | 适用内容 | 模板提示 |
|---|---|---|
| 观看契机 | （§6.6 冻结清单新增，未在 §5.3 展开模板） | — |
| 系列联系 | 前作、续作、单元故事或角色回归 | 与哪部作品或哪段故事关联？意义是什么？ |
| 其他作品联想 | 由本片想到另一作品 | 想到什么？相似、对照还是影响关系？ |
| 个人经历联想 | 与自己的生活和记忆相连 | 想起了什么？为什么在此刻被唤起？ |
| 现实／时代联想 | 社会议题、时代环境、当下争议 | 联想到什么现实语境？自己的态度是什么？ |
| 创作者／幕后 | 导演、Staff、制作过程等 | 哪项幕后信息改变了理解或观看感受？ |

### G. 影院与现场体验
| 类型 | 适用内容 | 模板提示 |
|---|---|---|
| 影厅效果 | 银幕、画幅、亮度、声音、座椅等 | 哪种效果最明显？是否值得为此制式再看？ |
| 观众反应 | 笑声、掌声、安静程度、应援等 | 现场观众怎样影响了体验？ |
| 舞台挨拶／映后谈 | 声优、Staff、主创现场或转播内容 | 谁参加？说了什么？哪个点值得保存？ |
| 特典／场刊 | 入场特典和场刊带来的记忆 | 得到了什么？与作品体验有什么联系？ |
| 现场事件 | 设备问题、特别互动、突发情况等 | 发生了什么？如何影响这次观看？ |
| 特别放映内容 | （§6.7 冻结清单新增，未在 §5.3 展开模板） | — |

### H. 自定义类型
用户需要填写：类型名称；所属分组或"自定义"；可选的一句提示；是否保存到个人类型库，供以后复用。自定义类型不上传为公共模板，也不自动改变系统预设类型。

> 备注：以上是 §5.3 展开了模板提示的版本；`FIELD_AND_TAXONOMY_FREEZE_V1.md` §6 的正式冻结清单在此基础上又补充了 5 个类型（改编处理、个人感悟、观看契机、特别放映内容，共 44 个），但没有再写模板提示——如果要恢复完整体系，这几个类型的模板提示需要重新补上。

## 四、类型选择辅助（`PRODUCT_DEFINITION_MVP_V1.md` §5.4）

当一个记忆点难以归类时，界面按以下优先级帮助选择：

1. 用户首先想保存的是什么；
2. 内容主体属于故事、人物、视听、个人反应、关联还是影院体验；
3. 仍无法判断时使用"被击中的瞬间"或自定义类型；
4. 不要求为了覆盖多个角度复制出多张相同内容的卡片。

## 五、新增卡片面板的交互设计（`PRODUCT_DEFINITION_MVP_V1.md` §3.5）

新增卡片不能先给一个完全空白的输入框。第一步展示可视化类型库，按七个分组排列。选择类型后，才出现对应模板。

面板必须支持：最近使用的类型；搜索类型；分组浏览；自定义类型；随时取消，不产生空卡片。

## 六、情绪标签体系（`PRODUCT_DEFINITION_MVP_V1.md` §4.1 F，共 46 个）

多选、可删除、可自定义。

| 分组 | 预设标签 |
|---|---|
| 愉悦体验 | 开心、有趣、可爱、浪漫、温暖、心动、满足、爽快、治愈 |
| 强烈触动 | 感动、震撼、兴奋、热血、落泪、共鸣、敬佩 |
| 消极体验 | 悲伤、压抑、愤怒、恐惧、不适、恶心、失望、遗憾、无聊、反感 |
| 认知反应 | 意外、困惑、受到启发、开拓视野、想深入思考 |
| 持续感受 | 怀念、向往、意犹未尽、空虚、后劲很大、久久不能释怀 |
| 沉浸状态 | 紧张、代入、沉浸、着迷、忘记时间 |
| 交流冲动 | 想讨论、想推荐、想吐槽、想找同好 |

每个被 AI 建议的标签可以保存：标签 ID、显示名、分组、证据、置信度、明示／推测状态。用户自定义标签应明确标记为 `custom`，但使用体验与预设标签一致。

冻结规则（`FIELD_AND_TAXONOMY_FREEZE_V1.md` §5）：预设标签共 46 个，完整但不平铺；用户可以新增自定义标签，不自动成为全局预设；近义口语优先映射（例如"难绷"可映射为有趣、尴尬或自定义，不能机械固定）；态度与情绪独立，"超喜欢＋遗憾""不喜欢＋可爱"都合法。

## 七、AI 结构化输出规范全文（`PRODUCT_DEFINITION_MVP_V1.md` §6，与卡片直接相关的部分）

### 6.1 AI 的职责

AI 负责：
- 从原文中提出一个个人态度建议和最多一个备选；
- 提取有依据的情绪反应；
- 将零散感想拆成若干记忆卡片；
- 在原文明示时提取观看场景信息；
- 提出后续关系建议，但不替用户确认；
- 用户主动选择推荐值后，依据原文协助整理推荐对象、理由、注意事项或不推荐原因；
- 为自动判断提供原文证据和置信度；
- 识别原文是在描述一次观看，还是同时比较多次观看；
- 在独立的票务解析流程中，从已经去除敏感信息的预订邮件文本提取观影字段。

AI 不负责：
- 润色、摘要或重写原始感想；
- 上网补充作品资料或公共评价；
- 猜测用户未表达的观看经历；
- 为了填满结构而制造内容；
- 自动决定用户未来会做什么；
- 直接保存、导出或同步正式记录。

### 6.2 AI 输入

感想分析默认只提供：作品名；作品类型（若用户已填写）；影院特别放映的集数范围或放映内容说明（若用户已填写）；本次记录类型；本次原始感想；已由用户建立或票务导入的候选观影场次；用户已主动填写的少量上下文字段。

重看时默认不提供旧记录正文。用户未来可主动启用"对照旧记录分析"，但不属于 MVP。票务邮件文本不与感想正文拼接，也不进入态度、情绪、记忆卡片和推荐判断。

### 6.3 强制行为规则（15 条）

1. 原文没有提到的信息返回空数组或 `null`。
2. 不得把电影常识、剧情百科或网络口碑当成用户观点。
3. 每个态度、情绪和卡片建议都必须附带至少一段原文证据；推荐值不由 AI 建议。用户先选择推荐值后，AI 协助整理的推荐条件字段也必须有原文证据，没有证据则保持空白。
4. `explicit` 只用于原文直接表达；需要解释才能得出的内容标记为 `inferred`。
5. 推测必须保守，态度复杂或不明确时优先建议"不好说"。
6. 证据使用原文短片段，不得改变措辞；同一片段可以支持多个相近判断。
7. 不因错字、口语、重复、跳跃或清单结构降低对原文的尊重。
8. 不把"作品完成度"转换成分数。
9. 不生成原文未提及的记忆卡片类型来追求覆盖率。
10. 返回内容必须符合固定结构；自然语言解释只能出现在规定字段中。
11. 原文明确比较多次观看时，分别提出观影场次草稿，并让同一感想关联多个场次；不得复制原文建立多份感想。
12. 页面发布日期、作者所在地和条目上映日期不能被当作观影时间或影院地点。
13. 必须区分用户自己的感受、用户的解释推测、文中引用或转述的他人说法，以及来源平台元数据。
14. "据说""朋友认为""导演承认"等转述不能被 AI 改写为已经核实的客观事实。
15. 用户明确赞同一段引用时，应分别保存被引用内容与用户的认同，不能把两种声音合并。

### 6.4 输出顶层结构（产品级数据约定，非最终 Schema）

```json
{
  "schema_version": "0.1",
  "analysis_id": "analysis_xxx",
  "input_hash": "...",
  "attitude": {},
  "emotions": [],
  "memory_cards": [],
  "viewing_event_suggestions": [],
  "linked_viewing_ids": [],
  "follow_up_suggestions": [],
  "recommendation": {},
  "warnings": [],
  "analysis_metadata": {}
}
```

### 6.5 通用证据结构

```json
{
  "excerpt": "原文中的短片段",
  "basis": "explicit",
  "voice": "user",
  "claim_mode": "direct_feeling",
  "explanation": "为什么这段原文支持该建议",
  "confidence": 0.92
}
```
约束：`basis` 只能是 `explicit` 或 `inferred`；`voice` 使用 `user`、`quoted_other` 或 `source_metadata`；`claim_mode` 使用 `direct_feeling`、`observation`、`interpretation` 或 `reported_statement`；`confidence` 范围 0-1，界面映射高／中／低；`excerpt` 必须能在当前原文中找到；`explanation` 简短、非评价式，不得扩写成影评。

### 6.6 个人态度输出

```json
{ "suggested": "like", "alternative": "mixed", "evidence": [], "confidence": 0.88 }
```
约束：`suggested` 必须是五个态度之一；`alternative` 最多一个，无合适备选时为 `null`；AI 不返回"暂不判断"；文本没有明确总体态度但含矛盾感受时建议 `mixed`；最终值必须由用户确认。

### 6.7 情绪反应输出

```json
{ "tag_id": "emotion_moved", "label": "感动", "group": "强烈触动", "evidence": [], "confidence": 0.94 }
```
AI 优先使用预设标签。只有原文中出现明显且无法由预设标签表达的反应时，才建议自定义标签，并标记 `is_custom_suggestion: true`。

### 6.8 记忆卡片输出 —— 这是最核心的一段

```json
{
  "temporary_id": "card_1",
  "type": "scene",
  "title": "哆啦A梦毁掉云之王国",
  "content": "哆啦A梦亲手毁掉与大雄共同建造的云之王国。",
  "why_it_matters": "原文将这一决定视为责任与决心的体现。",
  "related_emotion_tag_ids": ["emotion_moved"],
  "is_core_suggestion": true,
  "evidence": [],
  "confidence": 0.95
}
```
约束：
- 一张卡片聚焦一个主要记忆点；
- `content` 应忠实整理，不得添加原文没有的情节意义；
- `why_it_matters` 无依据时为 `null`；
- `is_core_suggestion` 只是建议，用户确认前不成为核心记忆；
- **相似卡片应合并，避免同一原文片段产生多张近义卡片；**
- **明显独立的多个点必须分开，不能压缩为一张综合影评卡片。**

（后两条就是当初设计里"分析、提炼"的核心动作——判断哪些该合并、哪些该保持独立，而不是逐句切分。目前实际提示词里只保留了"不能压缩为一张综合影评卡片"这一半。）

## 八、技术层面：Schema 与冻结稿的关系（`TECHNICAL_SOLUTION_AND_IMPLEMENTATION_PLAN_V1.md` §2.6）

几条和卡片设计直接相关的技术约定：

> "JSON Schema 的枚举直接来自冻结稿，输出后再做 Zod 校验和证据 excerpt 原文可定位检查。"

也就是说，当初的技术设计里，44 种卡片类型／46 个情绪标签本该原样进入 AI 输出的 JSON Schema 枚举，而不是像现在这样自建一份 16 项的子集。

> "限制输出卡片数量只依据原文内容，不为省钱截断原文。"

这条直接对应现在 schema 里硬编码的 `maxItems: 7`——当初的设计意图是卡片数量应该由内容本身决定，不应该为了控制成本或简化而设上限。

> "使用 12 条代表集做模型、prompt 和 reasoning 的回归比较。"

这句话说明当初是打算用 `VALIDATION_DATASET_V1.md` 里那 12 条案例做持续回归测试的，但实际只跑过 `AI_VALIDATION_REPORT_C3.md` 里 7 个短句级别的态度分类案例，12 条代表集里涉及长评合并/拆分判断的案例从未被真正验证过。

## 九、成品页面里卡片怎么呈现（`INTERACTION_DESIGN_REVISION_V2.md` §4 S6）

> "记忆卡片使用真正的卡片阅读方式：一次完整显示一张，通过分页或手势切换，不用截断下一张暗示滑动；单张卡片只展示类型、标题和一段内容，证据、关联场次、改类型等进入卡片菜单；成果页直接提供编辑当前卡片与添加新卡片的入口。"

需要注意：这条"一次显示一张、分页切换"的规则后来被 R3 阶段推翻，改成了纵向滚动一次显示完整卡片列表（这是显示布局层面的改动，不影响这里说的"证据、关联场次进入卡片菜单"这条信息架构原则——但当前代码里 `related_emotion_tag_ids`、`linked_viewing_ids` 这些字段本身就不存在，所以也无从谈"放进卡片菜单"）。

## 十、"好卡片"应该长什么样：案例文档里的具体判断过程

`docs/validation/CASE_001_DORAEMON_SHORT_REVIEW.md` 针对一段真实感想原文，完整写出了 AI 应该如何做合并/拆分判断，例如：

- 把"核威慑被利用"和"哆啦A梦亲手毁掉云之王国"两个情节点合并成一张卡片，理由："这一段保留为一张卡片，因为二者在原文中构成同一条因果链，拆成两张会割裂用户被打动的原因。"
- 两个都是"可爱/有趣的瞬间"类型的片段不合并，理由："用户分别记住了两个独立场景，合并会损失原始清单式感想的颗粒度。"
- 案例总结出的产品规则：**"卡片数量不能预设上限，未来长评应通过合并重复观点控制数量，而不是机械截断。"**

`CASE_002_KIKIS_DELIVERY_SERVICE_REVIEW.md`、`CASE_003_SMT_TICKET_EMAILS.md` 是另外两个案例（后者是票务邮件解析案例，跟卡片内容设计关系不大），如果要重新设计提示词，这两份案例文档、以及被提到但从未真正跑过的 `VALIDATION_DATASET_V1.md` 里那 12 条代表集，值得作为新提示词的测试基准去逐条过一遍。

## 十一、冻结变更规则（`FIELD_AND_TAXONOMY_FREEZE_V1.md` §13）——如果决定要改，当初设想的门槛

> "冻结含义：除非真实原型测试证明无法完成记录，否则不再增加核心模块、态度选项或顶层实体。"

后续新想法按以下顺序处理：

1. 能否用现有字段表达；
2. 能否用自定义标签或自定义卡片表达；
3. 能否作为类型模板提示，而不是新字段；
4. 是否由至少两个真实案例证明是重复需求；
5. 是否会增加普通记录流程的思考负担。

> "只有同时证明'现有结构无法表达'和'重复出现'时，才允许修改冻结基线。"

这条规则本身也可以重新讨论——它是当初为了防止过度设计定的门槛，但既然现在准备重新审视整个卡片功能，这条门槛要不要保留、怎么调整，也是可以一并考虑的问题。
